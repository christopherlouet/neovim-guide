# Parcours guidé

Ce guide peut être lu de plusieurs façons selon ton niveau et tes besoins.

---

## Débutant — Les fondations

**Objectif** : Comprendre Neovim et être productif pour les tâches de base.

1. **Introduction** — Pourquoi Neovim peut remplacer IntelliJ
2. **Mental Model** — Modes et philosophie Vim
3. **Navigation** — Se déplacer sans souris
4. **Édition** — Modifier efficacement

**Durée estimée** : 1 semaine à raison de 1h/jour

---

## Intermédiaire — Productivité quotidienne

**Objectif** : Maîtriser le workflow de développement complet.

1. **Diagnostics** — Lire et corriger les erreurs
2. **LSP** — Autocomplétion, navigation, refactoring
3. **Qualité** — Formatters et linters
4. **Git** — Workflow Git intégré
5. **Terminal** — Tests et debug

**Durée estimée** : 2 semaines

---

## Avancé — Outils professionnels

**Objectif** : Exploiter tout le potentiel de la configuration neovim-intellij-ide.

1. **Navigation avancée** — Harpoon, Leap, Aerial, Marks
2. **DevOps** — Kubernetes, Terraform, Ansible, Docker
3. **Database** — Requêtes SQL avec vim-dadbod
4. **HTTP/REST** — Tester des APIs avec rest.nvim
5. **GitHub** — PRs et Issues avec Octo.nvim
6. **AI Assistance** — Claude Code intégré

**Durée estimée** : 2-3 semaines

---

## Expert — Personnalisation

**Objectif** : Adapter Neovim à tes besoins spécifiques.

1. **Configuration** — Comprendre la structure Lua
2. **Customisation** — Modifier en sécurité
3. **Workflow React** — Optimisations spécifiques
4. **Autonomie** — Maintenir et évoluer seul

**Durée estimée** : Continue

---

## Parcours par rôle

### Développeur Backend
1. Introduction → Mental Model → Navigation
2. LSP → Diagnostics → Qualité
3. Git → Terminal (debug)
4. Database → HTTP/REST
5. DevOps (si applicable)

### Développeur Frontend
1. Introduction → Mental Model → Navigation
2. LSP → Diagnostics → Qualité
3. Git → Terminal (tests)
4. Workflow React
5. HTTP/REST (APIs)

### DevOps / SRE
1. Introduction → Mental Model → Navigation
2. Terminal → Git
3. DevOps (Kubernetes, Terraform, Ansible)
4. Database (monitoring queries)

### Fullstack
1. Tout le parcours Débutant + Intermédiaire
2. Tous les outils avancés
3. Personnalisation

---

## Conseils d'apprentissage

### Ce qui fonctionne
- Pratiquer 30-60 min par jour
- Un concept à la fois
- Garder IntelliJ comme backup initial
- Utiliser Which-key (`<leader>` + attendre)

### Ce qui ne fonctionne pas
- Essayer de tout apprendre d'un coup
- Abandonner après une semaine
- Ignorer les raccourcis clavier
- Ne pas lire les messages d'erreur

---

## Checklist de progression

### Niveau 1 : Survie
- [ ] Je peux ouvrir, éditer et sauver un fichier
- [ ] Je comprends les modes Normal/Insert
- [ ] Je navigue dans un fichier avec `hjkl` et recherche

### Niveau 2 : Productif
- [ ] J'utilise `<leader>ff` et `<leader>fg` naturellement
- [ ] Je navigue à la définition avec `gd`
- [ ] Je corrige les erreurs avec `<leader>ca`
- [ ] Je fais des commits avec le workflow Git

### Niveau 3 : Efficace
- [ ] J'utilise Harpoon pour mes fichiers principaux
- [ ] Je saute avec Leap instantanément
- [ ] Je gère les PRs depuis Neovim
- [ ] Je teste les APIs avec rest.nvim

### Niveau 4 : Expert
- [ ] Je personnalise ma configuration
- [ ] Je contribue au projet neovim-intellij-ide
- [ ] J'aide d'autres développeurs à migrer
